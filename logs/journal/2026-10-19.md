## Findings and surprises

- `ug claude` manages Claude Code's managed-settings file, which conflicts with our read-only policy. Its extras (plugin, hooks, local MCP proxies) are blocked by our policy anyway.
- On Foundry, **WebSearch runs on the server side**, so the firewall can't stop it. Only a managed deny rule does ([ADR-016](../decision-log.md#adr-016)).
- Foundry alone can't cap spend per user. The Claude apps gateway can, and a `"0"` cap stops one developer on their next request. An org-wide zero cap doesn't override per-user caps, so it isn't a full kill switch.
- Windows-only .NET/VB.NET code can't build in a Linux container. Three capability tiers instead ([ADR-017](../decision-log.md#adr-017)).
- On the isolated VDI, a container-firewall failure would be hidden by the VDI firewall. Portable tests need an internet-connected host ([NET-014](../../docs/03-test-plan/catalog/network.md#net-014)).
